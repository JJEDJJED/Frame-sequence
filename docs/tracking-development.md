## 当前行为：跟踪中心驱动，禁止轮廓居中

2026-10-23：根据实际旋转素材反馈，撤销上一版以轮廓包围盒中心作为居中基准的做法。下文早期轮廓居中章节保留为历史记录，不代表当前行为。

- 首个选点定义居中基准；其他选点及最多 12 个自动局部前景辅助点用于估计运动。首帧人工中心可定义独立的虚拟中心。
- JavaScript 使用点对一致性筛选和最小二乘相似变换，允许旋转与缩放；不再用点间相同平移作为可靠条件。辅助点发生非刚性形变而无法拟合时，仍可使用独立一致的人工选点。
- Python 保留官方模型可见性阈值与原始标志。正向跟踪后，以约 4 帧间隔的可靠帧为锚点执行分段反向跟踪；同时满足回到锚点的循环误差、正反向位置一致和前景条件，才恢复低可见性坐标。不会仅因点落在人物上就改成可用。
- `visibility` 为最终可用性，`modelVisibility` 为原模型可见性，`pointStatus` 区分 reference / tracked / confirmed / recovered / lost；自动辅助点存于独立的 support 字段，不改变人工选点身份。
- 失效区间仅按帧时长在前后可靠中心间插值，首尾失效保持最近可靠中心，均提示检查。完全无轨迹、标记过期或模型不可用时保留原图，不使用轮廓中心。
- 轮廓数据仅用于保留像素范围和内部诊断，预览移除黄色轮廓框。蓝线表示画布中心，黄色十字表示所采用中心；点颜色说明已显示在卡片中。
- 估计旋转和缩放仅用于定位中心；输出不旋转、不缩放，保留原像素及时间信息，只做整数平移。最多半像素的数值取整误差不代表人体中心估计准确率。

## 数据与接口

- `GET /api/tracking/status`：环境是否准备好、缺失依赖和忙碌状态；不加载模型。
- `POST /api/projects/:projectId/tracking`：提交 `assetIds`、`width`、`height`、首帧 `points`，返回 202 和任务 ID。
- `GET /api/projects/:projectId/tracking/:jobId`：读取状态、逐帧进度、结果或错误。
- `DELETE /api/projects/:projectId/tracking/:jobId`：取消任务。

外部请求不能指定本地图片路径；服务端通过项目素材 ID 解析路径。一次只运行一项跟踪任务，最多保留最近 20 项任务；任务进度随 Node 服务重启消失，已完成的轨迹则由前端保存到项目参数。

结果使用原图坐标 `[帧][点][x,y]`，同时保存模型可见性、验证后可用性和点状态。非有限坐标保存为 `null`，越界和未经验证的不可见点不参与拟合。首个选点或首帧人工中心定义居中基准，多点拟合将其投影至后续帧；失败时使用轨迹插值 / 保持，不使用轮廓中心。

旧版只水平校准、目标轨迹和任意平移修正与“每帧正中心”目标冲突，现已停止应用。输入内容指纹决定轨迹、参考点和人工中心是否仍有效。人工中心使用独立指纹，因此同一素材重新跟踪不会丢失中心标记。

## 修复：点击跟踪显示「接口不存在」

2026-10-23 在实际 5288 服务复现：`GET /api/tracking/status` 返回 404，同时新前端文件能正常加载。该 Node 进程从 11:18 开始运行，早于跟踪路由加入；静态文件按请求读盘，后端代码则仍是旧进程启动时加载的版本。

先添加回归测试，确认客户端仅显示泛化错误、重复启动旧实例仍成功退出这两个断言失败，再修复：

- 跟踪接口明确返回「接口不存在」时，客户端提示重启本地服务和刷新页面；任务不存在等具体错误仍保留原消息。
- 端口已占用时，启动程序先检查现有实例的跟踪接口。旧实例或无法正常响应的服务会提示关闭原启动窗口并重启，不再静默打开不兼容的服务。
- 重启实际旧实例后，GET 跟踪状态返回 200、`ready: true`；对提交接口的无效空请求返回 400「画布尺寸无效」，证明已进入新路由的参数校验，且没有创建任务或修改项目。

## 修改目标：每帧人物主体位于画布正中心

原先相对首帧对齐的逻辑不能满足此目标。实际 24 帧素材的首帧输出约向左偏 68 像素，20 帧在跟踪不可靠时保留原位。现替换为以下流程：

1. 对透明图做 8 连通轮廓分析，过滤独立小杂点，单独保留所有非零 Alpha 内容的范围，以防裁掉淡光。
2. 首帧参考点辅助选择主要轮廓；后续可靠跟踪点辅助在多个候选中选择人物。不可见、越界、异常坐标或位移不一致时，依据主体面积和相邻位置选择轮廓回退。
3. 默认使用选定轮廓包围盒中心；人工中心标记可处理与人物连在一起的刀光等内容。所有中心都来自原图像素坐标。
4. 先确定整段统一画布，按所有可见内容相对人物中心的最大距离对称扩展；再用最终画布中心计算整数偏移。各帧相对数学中心最多相差 0.5 像素，保持像素尺寸、帧数与时长。
5. 空帧保持透明，使用邻近非空帧中心插值作为内部占位。全部跟踪缺失、模型不可用或轨迹过期也继续轮廓居中。多主体无法可靠区分时提示确认，允许人工标记。
6. 人工中心、首帧选点和轨迹均校验输入指纹。旧图片的选点不能误选新图片上的光效，同一图片重新跟踪会保留中心标记。旧的单轴 / 轨迹模式与任意偏移不再参与计算。

TDD：先添加 11 项居中几何测试和 5 项轮廓分析测试，观察首帧偏移等真实断言失败后实现；再添加节点输出、元数据保留、旧数据失效和人工中心保存测试。额外回归测试分别复现并修复旧参考点误选新图片的小光效，以及鼠标标记混入预览缩放元数据的问题。旧版 6 项相对首帧位移测试由新目标的断言替代。

实际素材验证使用独立项目副本：309×165、24 帧，复用既有轨迹时 20 帧使用轮廓回退；所有帧中心误差均 ≤0.5 像素，画布保持 309×165，所有可见内容都在输出范围内。浏览器验证清空全部轨迹时仍能居中；在第 13 帧标记 `(137,54)`，刷新及重新执行真实 GPU 跟踪后标记仍有效。已完成原图 / 居中切换、回退提示和中心辅助线检查。

最终验证：38 项 Node 测试与 11 项普通 Python 测试通过，95 个 JavaScript 文件语法检查、Ruff 和 uv 锁文件一致性检查通过；真实模型单元测试默认单独开启，本次另外通过浏览器对实际 24 帧素材执行了真实 CUDA 跟踪。
